# IRS Protect Plus — website

A fully static, bilingual marketing and member website for **IRS Protect
Plus**, the membership program from Best Vision Accounting, LLC. Spanish pages
live at the site root and English pages under `/en/`. No framework and no
server-side code. A small build script (see section 2) generates the English
pages, the SEO tags and the sitemap; its output is committed, so the site
deploys as plain files.

All program facts on the site (the $19.99 monthly fee, up to $10,000 in
professional representation, the notice-date rule, future-tax-year coverage,
exclusions, cancellation and refunds, Florida governing law) come from the
IRS Protect Plus Membership Agreement.

## Pages

| File | Purpose |
| --- | --- |
| `index.html` | Landing page (hero, trust, how it works, membership, coverage rules, what's included, FAQ, CTA) |
| `enroll.html` | Enrollment: review & accept the terms (price, auto-renewal, cancellation, three required boxes) → details and payment on Stripe's secure Checkout page, in the visitor's language. The dashboard creates that page, activates the membership from Stripe's payment and emails the welcome; Stripe's return shows a thank-you or a "not charged" note |
| `submit-notice.html` | Anyone uploads an IRS notice (PDF/JPG/PNG/HEIC, drag & drop, validation); the files go privately to the IRS Protect Plus dashboard |
| `contact.html` | Contact form + contact details |
| `help.html` | Help center: FAQ + how-to topics |
| `login.html` | Member sign-in (links to your portal when configured) |
| `membership-agreement.html` | The Membership Agreement, verbatim in English, with a Spanish courtesy translation |
| `terms.html`, `privacy.html` | Terms of Service and Privacy Policy, Spanish and English |
| `404.html` | Not-found page (set it as the custom 404 page on your host) |
| `en/*.html` | English versions of the pages above. **Generated, do not edit by hand.** |
| `sitemap.xml`, `robots.txt` | Generated by the build. |

Shared code: `css/site.css` (all styles), `js/i18n.js` (every Spanish and
English string), `js/site.js` (navigation, forms, accordions), `js/config.js`
(**your settings**).

## 1. Configure the site — edit `js/config.js`

Everything business-specific lives in this one file. Every value is optional;
blank values degrade gracefully.

| Setting | What it does |
| --- | --- |
| `company.email`, `phone`, `hours`, `address`, `url` | Shown on the Contact page, the footer and the legal pages, and used as the email fallback for forms. Blank rows are hidden automatically. |
| `company.streetAddress`, `city`, `region`, `postalCode` | The same address split into parts for search engines (structured data). Keep it identical to your Google Business Profile. |
| `dashboardUrl` | The IRS Protect Plus dashboard (`https://app.irsprotect.us`). The notice form uploads each file privately to it, then it records the notice, emails the receipt in the visitor's language and alerts the team; `/enroll` asks it for the Stripe Checkout page; the contact form posts each message to it, and it emails the office (Reply answers the visitor) and notes it in GoHighLevel. On `localhost` the site uses a dashboard on port 3000 instead. The dashboard must list this site's origin in its `MARKETING_SITE_ORIGIN`. |
| `memberPortalUrl` | The member portal (`https://app.irsprotect.us`, the same app). Every "Iniciar sesión / Log in" link opens it. |
| `billingPortalUrl` | Stripe's customer portal login link. Members update their card or cancel there; `/refund-policy` lists it as the online way to cancel and `/login` links it. Blank hides both links. |
| `forms.endpoint` | Optional, contact form only, and only when the dashboard can't take a message (not set up, unreachable): where it POSTs instead (multipart/form-data, e.g. Formspree). If blank, it opens the visitor's email app addressed to `company.email`. |
| `maxUploadMb`, `maxFiles` | Notice upload limits, matching the dashboard's (25 MB per file, 10 files). |

### Production setup

Notices and payments run through the IRS Protect Plus dashboard: notices go
to its private storage, and payments to the client's Stripe account through a
Checkout page the dashboard creates (the dashboard then records each payment
in GoHighLevel). The site holds no Stripe key and no form service. What must
stay true: the dashboard answers at `dashboardUrl` and lists this site's
origins in `MARKETING_SITE_ORIGIN`.

## 2. Build (after any change to pages, text or config)

```
cd scripts
npm install      # first time only
npm run build
```

The build (`scripts/build.mjs`):

- writes the head of every page: title, description, canonical URL,
  hreflang language links, Open Graph share tags, structured data
  (JSON-LD) and the Vercel analytics tags
- generates the English pages in `en/` from `js/i18n.js`
- converts images to WebP and makes the share images in `assets/og/`
- writes `sitemap.xml`, `robots.txt` and the IndexNow key file

It is safe to run repeatedly. Commit its output. The site's domain is the
`SITE` constant at the top of `scripts/build.mjs`.

## 3. Run locally

```
npx serve -l 8000 .
# then visit http://localhost:8000  (serve supports clean URLs like /enroll)
```

Port 8000, not serve's default 3000: on localhost the notice form talks to a
dashboard running on port 3000 (`npm run dev:vercel` in the dashboard repo,
with `http://localhost:8000` in its `MARKETING_SITE_ORIGIN`).

## 4. Deploy

The site is deployed on Vercel from GitHub. `vercel.json` turns on clean
URLs (`/enroll` instead of `/enroll.html`, with automatic redirects from the
old addresses) and sets security and caching headers. `.vercelignore` keeps
`design-source/`, `scripts/` and the docs off the live site.

## 5. IRS notice guides

The guides live in `content/guides/` as pairs: `<name>.es.html` and
`<name>.en.html`. Each file starts with a JSON block (title, description,
URL path, headline, answer-first lead, dates, `reviewed`, `reviewer`)
followed by the article body. The build wraps them in the site header and
footer and writes them to `avisos-irs/` and `en/irs-notices/`.

A guide is published with `noindex` and left out of the sitemap until
`"reviewed": true` is set in **both** language files. Before flipping it,
have a credentialed professional (EA or CPA) check the facts against the
IRS.gov sources listed at the bottom of each guide, put their name and
credential in `"reviewer"`, update `"updated"`, and run the build.

## 6. Editing text

All copy, in both languages, is in `js/i18n.js`. Elements are marked with
`data-i18n="key"`. Page titles are the `title_*` entries and search-result
descriptions the `desc_*` entries. Change a string in `js/i18n.js`, run the
build, and it updates everywhere, in both languages.

## Legal pages

`membership-agreement.html` contains the IRS Protect Plus Membership Agreement
word for word in English (the governing version), plus a Spanish courtesy
translation labelled as such. The signature block of section 15 is presented as
a note that acceptance is recorded electronically at enrollment. The Terms of
Service and Privacy Policy were drafted to match the agreement (LLC, Florida
law, single product) and are provided in both languages. Have counsel review
the Spanish translations and the Terms/Privacy drafts before launch.

## Design source

`design-source/` holds the design-tool prototypes (`IRS Protect.dc.html`,
`IRS Protect v2.dc.html`, `support.js`) and the reference images in
`uploads/`. None of it is used by the live site, and `.vercelignore` keeps it
from being published.
